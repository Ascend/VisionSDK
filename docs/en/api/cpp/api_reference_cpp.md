# API Reference (C++)<a name="ZH-CN_TOPIC_0000001813361264"></a>

## Usage Notes<a name="ZH-CN_TOPIC_0000001813361156"></a>

> [!NOTICE]
>
>- For the classes exposed in this section, use a single class instance in one thread. Do not use the same class instance in different threads.
>- For functions whose input is an STL container or a webjson parameter, limit the container length based on performance and actual service requirements to prevent possible memory issues.
>- Do not include comments in JSON-related content passed to interfaces. Otherwise, parsing fails.
>- If a single object in JSON-related content contains key-value pairs with the same key, the interface keeps the last set of key-value pairs as the parsing result by default.
>- Some C++ interfaces are generated by the compiler, for example, default constructors, default destructors, and copy assignment constructors. This document does not describe them in detail.
>- Some interfaces and data structures are generated by `protobuf`. Note that `protobuf` automatically generates its internal custom classes and data structures. Do not use these `protobuf`-generated classes and data structures.

**Interface Management Conventions<a name="section125481420139"></a>**

- Interfaces marked with the macro `SDK_AVAILABLE_FOR_OUT` are open to you.
- Interfaces marked with the macro `SDK_AVAILABLE_FOR_IN` are for internal use. Do not use them.
- Interfaces marked with the macro `SDK_UNAVAILABLE_FOR_OTHER` are hidden, and you cannot use them.
- Interfaces marked with the macro `SDK_DEPRECATED_FOR` are deprecated in future versions. You are advised to use alternative interfaces.
